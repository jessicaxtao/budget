Canopy Budget
Design review · 23 October 2026
Typography / The Grove
A clearer voice for everyday money

Keep the warmth.
Give the numbers more clarity.

Use Inter throughout the working interface. The Grove’s parchment, canopy green, rounded panels, and Elder already give Canopy its character. A quieter type system makes the budget easier to read.

My recommendation: Inter 400 / 500 / 600.
Replace the serif wordmark and routine monospaced figures with one sans family. Use tabular digits in money columns and sentence-case labels.

Smallest-change alternative: unified DM Sans.
Keep our existing UI family, extend it to money, and simplify the labels. This is a strong option if Inter feels too neutral.

Four credible directions

02 / RECOMMEND

Ranked for this product’s warm visual identity and dense budget tables. These are design judgments, not a measured usability ranking or claims about which fonts competitors use.

01 / Best overall
Inter$12,408.65

Clear, composed, and familiar as application typography. Its screen-oriented design and tabular-number support make it a strong fit for frequent financial scanning. [7]

Tradeoff: less distinctive on its own. Our green chrome, parchment, and mascot should carry that work.

02 / Best continuity
DM Sans$12,408.65

The existing UI face is already suitable. Extending it to figures and the wordmark removes the competing voices while preserving the most familiar part of Canopy.

Tradeoff: the change is subtler. If the current rounded letterforms themselves are the problem, Inter will be more satisfying.

03 / Best humanist option
Source Sans 3$12,408.65

Open, approachable letterforms with a practical tone. Adobe designed the family for UI environments; it works well when long category and payee names dominate. [9]

Tradeoff: more understated than polished consumer fintech. Compare it at 14px for body rows before choosing.

04 / Best expressive option
Manrope$12,408.65

A more geometric, contemporary feel. Attractive headings and prominent balances could give Canopy a stronger consumer-app personality.

Tradeoff: its broad, stylized shapes need more care in dense rows. Use the open-source Google Fonts distribution shown here; newer designer releases may have different licensing. [10]

What the budget apps teach us

The Grove, with a simpler type system

04 / SPECIFY

Keep our existing visual identity

Preserve the canopy header, parchment canvas, paper surfaces, warm dark mode, rounded panels, thin row rules, semantic money colors, and Elder mascot. Those are sufficient to make Canopy recognizable.

Canopy#1F4A36
Parchment#F6F1E7
Bark#2B211B
Coin#F2B632

Light palette swatches. The preview’s dark mode uses the existing warm dark tokens from src/index.css.

Change the typography’s job allocation

  • One sans for the product. Use Inter for the wordmark, page titles, navigation, controls, and money. Keep the working interface at 400–600; reserve 700 for an occasional active state.
  • Tabular digits, not monospaced text. Equal-width digits align money while letters retain natural spacing. Use proportional figures for large standalone balances.
  • Sentence case for labels. Replace 11px, 0.08em-spaced uppercase Plex Mono labels with 12px, 600-weight sans labels and normal tracking.
  • A serif is optional branding. If the Young Serif wordmark is important to the identity, it can stay as the only serif element. My preference for this direction is the sans wordmark shown above.

Why the current combination feels off

Young Serif makes the name feel editorial. IBM Plex Mono gives almost every amount a typewriter rhythm. Tracked uppercase headers reinforce the printed-ledger feel. DM Sans is already a capable UI font between those two stronger voices.

My diagnosis is the combination and frequency, not that any one of these families is unsuitable for finance.

Code is the source of truth: PageHeader.js already renders page titles in DM Sans, despite UI.md still describing Young Serif for page headings. DashboardSummary.js uses Plex Mono for values, and CategoryLedgerTable.js uses it for money and uppercase headers. These specimens follow the implementation.

Not shortlisted: another display serif preserves the same editorial emphasis; a separate display font adds complexity; an Apple-only font would make the Windows/Electron experience inconsistent. A system stack is viable if platform-native rendering is the priority.

Judge the digits, not just the heading

Test identical-width digit strings, cents, negative values, and long names at actual row size. Check both themes and 200% zoom before adopting a family.

A contained implementation

05 / APPLY LATER

Adopt the type roles together. A font-name swap alone leaves the small uppercase labels and monospaced money treatment in place.

  1. Bundle the chosen fonts locally, as the app already does through Fontsource. Start with upright 400, 500, and 600 plus any bold or italic actually used.
  2. Give currency its own semantic class. Replace routine figure uses of font-mono and apply tabular numerals explicitly to comparable columns.
  3. Update the label scale, case, and tracking; audit the hardcoded Plex Mono mobile labels in src/index.css as well as Tailwind classes.
  4. Review dashboard, register, money-entry modal, charts, and mobile reflow in both themes. Check long amounts, negative signs, currency glyphs, fallback loading, and zoom.
  5. Once chosen, update the typography rules in .claude/UI.md to match the actual implementation.

This review changes no production components, styling, or dependencies.

Proposed font roles

/* Recommendation, not applied to the app */
:root {
  --font-ui: "Inter", system-ui, sans-serif;
}

body, button, input, select, textarea {
  font-family: var(--font-ui);
}

.money-column {
  font-family: var(--font-ui);
  font-variant-numeric: lining-nums tabular-nums;
  text-align: right;
  letter-spacing: 0;
}

.hero-amount {
  font-variant-numeric: lining-nums proportional-nums;
}

.table-label {
  font: 600 12px/16px var(--font-ui);
  letter-spacing: 0;
  text-transform: none;
}
